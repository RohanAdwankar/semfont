A font that reads what you wrote

Every emphasis in your document is a claim you made by hand. The file records the bold, not the mattering — so when the sentence changes, the emphasis stays where it was. This one decides the typography from what the text means. Edit it and see.

Nothing above was marked up. Type into the box and the type follows.

The engine is not a model. It is four lexicons and about two hundred lines of rules, which is the entire point.

Four channels, four axes

A single sentiment colour is a gimmick. What makes this read as typography rather than as a highlighter is that the scores are independent and land on different axes, so they compose.

A word can be negative and hedged and the subject of the paragraph, and you see all three at once: dark red, leaning, heavy. Try that with bold and italic. Switch a channel off in the rail and the rest keep working — they are independent all the way down to the CSS.

Where this stops being a toy

Confirming a dangerous command. Every destructive prompt looks like every harmless one, which is exactly why nobody reads them. Send the confirmation text through the engine and the danger sizes itself:

WARNING: this operation is irreversible. It will drop 1.2TB of production user data immediately and there is no undo. Type the cluster name to continue.

WARNING, irreversible and immediately are in the salience lexicon; 1.2TB is a magnitude; production earned its weight by being the word the passage keeps circling.

Seeing your own hedging. Run a draft through the certainty channel and every might, maybe, seems leans away from you — and drags its clause with it.

Negation, which is where naive versions die. These two sentences are made of the same words.

The launch was great and the numbers were excellent.
The launch was not great and the numbers were not excellent.

The second renders red, but paler red than a sentence of genuinely nasty words: not great is a complaint, not a catastrophe. One rule — on hitting a negator within three content words, flip the sign and multiply by 0.74. Sentiment analysis has known that number since VADER; it is still the difference between a demo and a thing you would ship.

Why the boring engine is the feature

The obvious implementation is to send the paragraph to a model and get spans back. It would handle sarcasm. It would also cost a few hundred milliseconds, an API key, a network, and a copy of your draft on someone else's machine — per keystroke.

The number in the corner of that box is the whole argument. Scoring is synchronous and pure: a page of prose in about a millisecond, no network, no key, the same answer every time. That gap is not an optimisation, it is the distinction. Something you invoke is a feature. Something that is simply how the text looks, the way italics are, is a font — and it only gets to be one if it can run inside the input event, during a server render, on a plane.

The lexicons are also small enough to read in one sitting and to argue with. When the styling is wrong you can see which entry did it and fix it in one line, or teach it your own vocabulary. Nobody has ever fixed a model that way.

<SemanticText
  lexicon={{ valence: { flaky: -0.7, oncall: -0.4 } }}
  text={incident}
/>

Restraint is the design

The first version styled every word it had an opinion about and looked like a ransom note. The thresholds in the default theme are now high enough that most words come out untouched — a paragraph typically styles four or five. Emphasis is a contrast effect; it exists only relative to text that was left alone. Push sensitivity up in the rail to watch that stop being true.

The other constraint is that colour is never the only signal. Switch the theme to monochrome and all four channels ride on weight, size, slant and tracking instead — the accessible answer, and the better looking one in print.

Where it fails

It reads words, not arguments. It will not notice that a perfectly calm sentence is describing a catastrophe, it does not get sarcasm, and it speaks only English. A model would beat it on all three.

It would also never be a font.

Using it

import { SemanticText } from 'semfont';

<SemanticText as="p">{incident}</SemanticText>

One React component, no build step, no dependency but React. Take only the part you want: channels={['valence']} for colour and nothing else, a theme object to move which axis a channel drives, useSemanticText for the scores with your own rendering, or analyze(text) for four numbers per token with no React and no CSS at all.
